# antislop design proposal 003, 22 November 2026

Mode: **after** (global preference). Scope: the popup, the side panel and the archive page's Export section at version 1.7.3, commit `7e6d6ed`. Direction: [DESIGN.md](../DESIGN.md), dial ENERGY 1 / RHYTHM 1 / MOTION 1.

You asked for ideas from the *Teams Chat Exporter* extension, adapted to this extension and not copied. It was studied for layout and interaction only (R-30). The sources were its Chrome Web Store listing and the demo popup and screenshots on its website.

Only the rename to *Teams Chat Scraper* is done, as its own commit. Nothing below has been changed yet. Pick the numbers to build; numbers you don't pick stay as they are.

These are proposals, not rule findings, so the priority means something else here:
- **HIGH** fixes a problem measured on the page today;
- **MEDIUM** is a pattern from your list;
- **LOW** is polish.

None of them touches the scraping engine, the selectors, the database, or the export and import code. Every change is to markup, CSS or the interface scripts in `src/ui/`. Number 4 also needs one new route, `#export` with a chat's key. Every function stays, and none moves out of reach.

## What you liked, and what it means here

| What you liked in the reference | Here |
| --- | --- |
| Clean, well-organised sections | Kept as they are: sentence-case headings, space between groups, no box around each group (DESIGN.md). The order of the Export sections stays. |
| Compact layout | The popup already uses 12 px steps. The space is lost on the Export page, where the conversation list pushes **Export** off the screen (9). |
| Clear conversation selection and export controls | A filter and chat-type chips above the list, more on each row, and a bar at the bottom that always holds **Export** (8, 9). |
| Format tiles instead of dropdowns | Tiles for the capture choice (1) and the export format (6). Segmented rows for the shorter choices (7). |
| Date range and content selection | A segmented row for the period (7), and the content as a compact two-column checklist (11). |
| A prominent primary button with clear progress | Progress shown in place of the controls it replaces. A bar fills only where the end point is known (3, 9). |

## How it was checked

The current pages were built from the source and opened in a browser against the archive seeded for audit 002: the 451-message *Design review* and a 1:1 chat with *Alice Andersen*.
- The popup was checked at 380 × 600 with a touch screen emulated.
- The Export page was checked at 1024 × 768 with a mouse.

Sizes are read from the rendered page.

## Proposals

### HIGH

**9. Export bar: Export stays in reach, with the file name and the progress.**

Measured at 1024 × 768:
- With 2 conversations, **Export** is at 696 to 728 px.
- Each further conversation adds a 26 px row, so from the 4th conversation the button is below the window's bottom edge. *Corrected in the follow-up:* this said the button would be about 1,970 px down with 50 conversations. In fact the list stopped growing at 220 px and scrolled inside itself, so the button went no lower than about 900 px.
- The Export screen's focal point is the button (DESIGN.md), and today it gets pushed off the screen.

Proposal:
- The last row of the Export card becomes a bar. It sticks to the window's bottom edge while the card is on screen. It has a 1 px top border and no shadow.
- Left side: *Will save* with the real file name, from the same function that names the download (`exportFileNameFor`), for example *Will save teams-archive-2026-11-22T09-30-00.zip*. The time in the name is the moment you click. For PDF it reads *Opens the print dialog in a new tab*.
- Right side: the button, which keeps its current label: *Export 2 conversations (ZIP)*.
- During an export:
  - the button reads *Exporting…* and ignores clicks;
  - the bar's line reads *Writing 1,204 messages, conversation 1 of 2*;
  - a 4 px bar shows conversation *i* of *n*.
- The result line (*Exported 902 messages from 2 conversations as …*) stays where it is today, as a live region.
- Below 760 px the bar stacks: first the line, then a full-width button.

Rule: Liveliness, focal point. DESIGN.md's focal point for Export is the button, and it should stay visible.

### MEDIUM

**1. Capture tiles in the popup.**

Today one select holds seven choices. A two- or three-line hint under it says what the chosen one does.

Proposal: four tiles in a 2 × 2 radio group. Each tile has a name and one line:

| Tile | Its line |
| --- | --- |
| **New messages** | *Since the last update, 3 days ago* |
| **A period** | *24 hours, 7 or 30 days, or from a date* |
| **Full history** | *Back to the chat's start* |
| **On screen** | *Only what is shown, no scrolling* |

- Choosing **A period** shows a segmented row under the tiles: *24 hours · 7 days · 30 days · From a date…*. *From a date…* shows the date field.
- All seven choices stay.
- The hint shrinks to one sentence. The 2-day re-check for edits moves into the **New messages** tile's detail when it is chosen.
- The button keeps naming the choice: *Capture new messages*, *Capture the last 7 days*.
- A tile is a control:
  - It takes the control border, as a button does. The selected tile gets the selected tint, the accent border and a visible radio dot, so colour is not the only signal.
  - The arrow keys move between tiles, as in any radio group.
  - Tiles are 44 px or taller on touch.

At 380 px the tiles take about 20 px more height than the select and its hint. The button stays above the fold, at about 395 px in a 600 px popup with touch sizes. Today it is at 331 to 375 px.

**3. Run progress in the popup.**

The block keeps its place: it replaces the capture card during a run. The changes:
- **A bar where the end point is known.** For *A period* and *From a date*, the run knows how far back it must go (`captureFrom`) and how far it has reached (`oldestReached`). A bar shows that share, with the text *Back to 14 Nov 09:12, going back to 15 Oct*.
  - It changes in steps as the numbers update, with no transition.
  - It is a `progressbar` with a text value.
- **Text only where the end point is unknown.** For **Full history** the chat's start is unknown, so there is no bar: only *Reached back to 3 Mar 2025*. For **New messages** the run usually takes seconds, so the counters are enough.
- **One line for the state and the run.** The phase badge, the run's name and the time taken share one line.
- **The run's buttons.** **Pause** and **Stop** share one row, Stop in the danger style. **Continue** takes Pause's place, as the primary button, while the run is paused.
- **What stays.** The four counters and the detail line (scroll steps, pictures saved).

This changes DESIGN.md's MOTION line, as described under [DESIGN.md changes](#designmd-changes).

**6. Format tiles on the Export page.**

The Format select becomes seven tiles in a radio group. Each tile has the format's name and one line about what it is for:

| Tile | Its line |
| --- | --- |
| HTML page | *To read in a browser, pictures included* |
| PDF | *Opens the print dialog to save a PDF* |
| Markdown | *For notes apps and wikis* |
| Plain text | *Just the words* |
| CSV | *One row per message, opens in Excel* |
| JSON | *Complete records, Import archive… reads it* |
| Knowledge package | *A ZIP for knowledge tools and backups* |

Layout:
- four tiles per row at 1024 px;
- two per row at 375 px;
- one per row below 320 px.

What stays the same:
- the longer sentence under the tiles (`#export-explain`), and **What is inside** for JSON and the package;
- the remembered choice, and *HTML page* as the first-use default. JSON is still never the default.

The tiles take the control border, the selected tint and a radio dot, as in 1.

**7. Segmented rows for packaging and the period.**

- **Packaging**, shown for HTML only, as today: *One file · ZIP with the pictures as files*.
- **Messages:** *All · 24 hours · 7 days · 30 days · A period…*. *A period…* shows the *From (included)* and *Before (not included)* fields under the row.
- Each row is a radio group drawn as joined buttons. The chosen one gets the selected tint and the heavier bottom edge DESIGN.md gives a pressed button.
- A row wraps onto two lines when it does not fit. Nothing scrolls sideways.

**8. A conversation picker you can search.**

Today the list is checkboxes with a name and a message count, plus **Select all** and **Select none**.

Proposal:
- **Above the list:**
  - a filter field, *Filter by name*;
  - chips for the chat types the archive holds, with counts: *All 2 · Group chats 1 · 1:1 chats 1*. A chip shows only for a type that is present.
- **Bulk selection:** **Select all**, **Select none** and **Select shown**. Select shown selects the filtered set only.
- **Each row:** the name, then in muted text the type, the messages and when it was last updated: *Design review · Group chat · 451 messages · updated 3 days ago*.
- **The count line** says what the filter hides: *2 of 2 selected (1 not shown)*.
- **No inner scroll area.** The list has none, so a phone never gets a scroll inside a scroll. Number 9 keeps **Export** in reach instead.

### LOW

**2. Resume in the capture button's place.**

When a run was interrupted, **Resume extraction** already becomes the one primary button. But it sits in a card above the capture card, while the demoted **Capture** button stays below it.

Proposal:
- one card, with **Resume extraction** in the button's place and its line: *It captured 1,204 messages, back to 3 Mar 2025*;
- **Start another capture instead**, which shows the tiles.

**4. Export this chat… after a run.**

The popup's result keeps **Open this chat in the archive**. After it, add **Export this chat…**, which opens Export with only this chat selected.

This needs one new route (`#export` with the chat's key), read by `archive.ts`. The export code is unchanged.

**10. Presets that show when they are in use.**

**Knowledge system** and **Full backup** become two tiles, each with its sentence as today.
- The tile whose choices match the form shows as selected, with the text *In use*.
- Changing any choice that departs from it clears the selection.
- Today the presets are plain buttons. Only the status line confirms a click, and later nothing shows that the form still matches a preset.

**11. The content as a compact checklist.**

The six content checkboxes go into two columns from 760 px. Each label is the noun with its explanation in muted text: **File attachments** *names and links*.

Choices the format fixes stay disabled, with the note that says why, as today.

**12. Choices and conversations side by side on wide screens.**

From 1200 px:
- the left column holds *Start from*, the format, the messages and the content;
- the right column holds the conversation picker;
- the bar (9) spans both.

Below 1200 px it is one column, as now. This one is optional: 9 already keeps **Export** in reach.

## DESIGN.md changes

DESIGN.md is updated for whichever numbers you pick:

- **Shape and space** (1, 6, 7, 10): tiles and segmented rows are controls. They take the control border, the 6 px radius and the 32 / 44 px minimum. Selected means the selected tint, the accent border and a radio dot or pressed edge. The rule that nothing inside a card gets a border of its own stays, for groups and sections.
- **MOTION 1** (3, 9): *Nothing animates on its own. A bar may show a share that is known (how far back a ranged capture has reached, which conversation an export is writing); it changes in steps, with no transition. Where the end is unknown, progress is text.*
- **Focal point** (2, 9): Export's focal point is the button in the bar at the bottom of the card. In the popup, **Resume extraction** takes the capture button's place.
- **Palette**: the accent's uses gain the selected tile's border and the progress bar. That is still one accent.

## Not taken from the reference (R-37)

You asked to keep the anti-slop principles. So the patterns below are dropped by default. Say *keep* for any one you want anyway.

| Pattern in the reference | Rule it breaks | Default |
| --- | --- | --- |
| Uppercase, letter-spaced section labels | R-06; DESIGN.md typography (sentence case, no tracking) | Drop: 13 px sentence-case headings, as now |
| An icon on each section heading and format option | R-04; DESIGN.md icons (only where a label won't fit) | Drop: the tile's line of text says what the icon would |
| Each section in its own bordered box | DESIGN.md shape (nothing inside a card gets a border) | Drop: space and a heading, as now; only the tiles, which are controls, get borders |
| A bar that moves while the end is unknown | MOTION 1 | Drop: text for those runs, a bar only for a known share |

These were left out for reasons of scope, not slop:
- **Export from the popup itself.** The choices fit the archive page, and number 4 opens Export from the popup.
- **Cancel during an export.** `runExport` has no cancel, and adding one changes the export pipeline, which you asked to leave alone unless needed. It can be its own change later.
- **An export history.** It needs new storage.
- **Team channels as a source.** The extension does not read them.

## What passes now and stays

- One primary button per view, in the accent. The run panel takes the capture controls' place. Every popup control is 44 px on touch. The side panel has no sideways scroll at 300 px. These were all measured in audit 002 and are unchanged.
- The Export order: preset, format and what it makes, conversations, messages, content, button.
- Light and dark themes, from the same tokens. The tiles and segmented rows use only tokens that exist, so `tests/unit/logo.test.ts` keeps covering their contrast.
